# 第二篇博客素材：AI 模仿写作风格

## 骨架（作者定的，原话）

宝玉的单人菜谱思路 → 学术界证明这条路有物理天花板（mode collapse）→ 但推理时还有解码参数、激活层干预这些提示词之外的杠杆 → X 上已经分化出「克制去味」和「借人格」两派，还有人在搭多 skill 集成的路子 → 回到自己做 skill 的实践，印证「从自己真实改稿提炼」这条路径。

## 一、单人菜谱思路

人工改稿，让 AI 总结规律，更新菜谱，循环。我们建 hhwyt-style 那次就是这个套路的手工版。

自动化版本是 TICL（Trial-Error-Explain In-Context Learning）：AI 自己生成候选稿、自己判断哪里偏离目标风格、自己生成「反面例子加为什么不对」的解释，再喂回提示词，不需要人逐句改。关键差异在于它显式生成反例和解释，不只喂正面范文。

## 二、天花板

纯 few-shot 偏弱：给两篇和给十篇差别有限，而且写两三段之后会飘回 AI 自己的通用腔调。

Catch Me If You Can（arXiv 2509.14543，EMNLP 2025 Findings）：400 个作者，每个模型 4 万多次生成，六个前沿模型。结论是结构化文体（邮件、新闻）能模仿，博客和论坛不行；范文四五篇之后收益递减；输出倾向于 default to an average, generic tone。这篇读过原文，可以直接引。

根子上的原因：RLHF 和对齐训练把输出往「评分员觉得安全通顺」的区域压，学术上叫 mode collapse 或 homogenization。范文是在跟一个被训练目标压平过的分布掰手腕。

为什么写长了会飘：自回归生成，模型自己写出来的内容会成为后续生成的主要上下文，喂进去的范文权重被不断稀释，预训练先验重新主导。这也是 TICL 要短循环迭代而不是一次生成到底的原因。

为什么规则清单比喂范文管用：规则是对采样分布的直接约束，等于直接说某类词的概率压到零；范文是让模型自己做模式归纳，信号弱、噪声大。「不用破折号」比「学着我的范文写」立竿见影，原理上就是这个差别。

## 三、提示词之外的杠杆

解码参数（temperature、top-p、repetition penalty）。模型每写一个字都在算一份概率表，提示词管「给它看什么」，解码参数管「怎么从表里挑」。永远挑概率最高的那个，结果最正确也最没个性。温度调高就是允许它偶尔挑一个概率没那么高但更有特点的字。聊天界面里这个开关锁死了，用 API 才能调。

激活层干预（activation steering / representation engineering）。模型处理每个字的时候内部会产生一堆数字，代表它此刻在想什么。研究者能在这堆数字里找到对应某种风格的方向向量，生成时直接加进去，把输出硬拽过去。不改提示词，不动权重。只有自己跑开源模型才用得上。

LoRA 微调。不重训整个模型，只训一小撮新增参数，把风格焊进权重，绕开推理时先验重新主导的问题。成本比想象中低。

一句话：提示词是在跟它说话，这两个是在拧收音机旋钮和直接拨它的脑子。

## 四、X 上的分化

两种相反哲学：Tw93 的 write 走克制路线，只负责去掉 AI 腔，不重组结构、不替你加人格，适合「我知道自己要说什么，只是写出来像 AI」的人，跟宝玉同路数。数字生命卡兹克的 khazix-writer 走反方向，把本人三年公众号沉淀的口吻、节奏、选题判断整套焊进 skill，用的人是在借他的人格写作。有个提醒很到位：长期套别人的强人格 skill，最后会变成模仿而不是表达。

多 skill 集成的路子：human-writing 专攻拆解 AI 结构感，冷静客观，适合长文；humanizer-zh 短句喘息感强，适合情绪流动的内容；ljg-plain 核心是概念拆解。做法不是选一个，而是搭一份桥接文档，链接所有 skill、写清各自擅长什么，每次改稿几个各出一版，摆一起比着改。

分阶段流水线：read 转 Markdown，hv-analysis 做纵横研究，learn 从大纲到成稿，最后才轮到 write 做自然化。跟一个 skill 包打天下的做法不同。

另外一层维度：卡兹克那套里带 HKR 选题质检法（趣味性、知识量、共鸣感），管的是「这个题值不值得写」，跟「写得像不像人」是两回事。我们之前讨论的全是后者。
