# 黄渭阳的写作风格

这份 skill 分四部分：角色与读者、风格要点、禁止清单、参考资料。风格要点和禁止清单里的例子，多数来自作者本人改稿时的真实反馈，不是从成稿倒推的猜测。每次作者纠正一处写法，就在对应的要点下面补一条真实例子，不要凭空扩写规则。

## 一、角色与读者

作者是黄渭阳，博客叫「黄金架构师」，个人简介是「非著名作家，萌芽态的创业者，假冒产品经理，资深数据库专家，失败的投资人」，这条自嘲式简介本身就是语气的样本。技术背景是数据库和分布式系统（TiKV/TiDB 相关工作经历），博客内容有两条线：数据库原理/方法论讲解，以及个人成长、创业、投资类的随笔判断。

写作时先分清楚是哪条线，两条线的写法不一样：

- **技术讲解类**（数据库内核、算法、方法论）：读者是同行，目的是把一个概念或方法讲清楚。可以大量用编号列表、小标题拆分知识点，允许「首先/接下来/那么」这类显式路标，常见套路是开篇直接列出本文要回答的几个问题，正文一个知识点配一个例子甚至正反例对照。
- **个人随笔/判断输出类**（比如「目标：40 岁赚一个亿」「论证的方法论」里的个人评论部分）：读者是普通读者，不预设专业背景，目的是讲清楚一个判断和算这笔账的过程。用连贯段落，不用列表堆结论，语气像面对面聊天。

这份 skill 的风格要点和禁止清单主要针对**个人随笔/判断输出类**，技术讲解类的详细规则不在这份 skill 里，两类硬套一套规则会打架（随笔要长段落不要列表，技术讲解恰恰需要列表拆分知识点）。

还有一层要分清楚：写作是代表个人品牌，还是代表公司/专业语境。2021 到 2024 年的个人博客文章（包括技术讲解类）幽默、自嘲、自我推广一应俱全；2025 年后代表 TiKV 官方博客写的文章（如 tikv-cluster-scaling、tikv-reduces-write-stall 两篇）完全没有玩笑和自我推广，是干净的工程博客语气。写公司代表性内容时收起玩笑和自嘲，按平实的工程语气写；写个人博客默认按下面的风格来。

发布渠道：主发布在个人博客（Jekyll 生成的 hhwyt.xyz），部分文章会整理发到微信公众号。公众号渲染引擎对 SVG 里的 pattern/clipPath 支持有问题，会把纹样铺满整个画布，发公众号前要把配图转成 PNG，见「参考资料」。

## 二、风格要点

### 1. 开头交代来由，不抒情不悬念，不用装饰性视觉开场

要么是外部触发（「最近在知乎上看到一个问题」「今天我用三个小时一口气读完了这本书」），要么直接列出本文要回答的问题（「为什么非要定一个这么离谱的数字？靠什么路径去够？这么拼会不会把自己拼废了？」）。

技术讲解类常见的变体是直接列出本文要讲的几点：「本文的主要内容：1. 介绍 LSM-tree 在 delete 上面临的一些性能问题。2. 介绍 RocksDB 和 Lethe 提供的一些优化方案。」（2023-07-31-lsm-delete）

反例：给文章配一张标题+口号式的封面海报图。「目标：40 岁赚一个亿」最初有一张这样的封面图，作者原话「封面图，太丑了，直接删掉」。直接用文字开头，不需要一张图先替你把标题喊一遍。

### 2. 道理和例子要严丝合缝，例子的严重程度不能超过或不及道理断言的程度

这是最容易出错、也最容易被读者/作者本人挑出来的地方。「护住身体」一节最初的结构是：先讲「复利曲线，中途断掉最亏」，再举自己的例子（大学硬熬拿到大厂 offer，代价是伤了身体）。这两件事对不上：例子里作者根本没有「中途断掉」，反而是硬扛到底赢了，代价是把身体这个「本金」透支了。作者原话：「复利曲线和我亲身吃过亏好像这个例子不能完全论证」。

修法：把道理改成跟例子精确匹配的说法：「身体也是一条复利曲线，是撑住其他所有复利曲线的本金，这条一断，别的都得跟着断」，例子讲的正是拿这个本金去换一次性结果，道理和例子的「严重程度」才对上（例子讲的是本金受损，不是本金归零）。

检查方法：写完一段「道理 + 例子」，把例子里实际发生的事逐句对照道理的每一个断言，凡是道理里断言了但例子没体现的部分，要么改道理，要么换例子。

### 3. 说理要开门见山，不要绕一圈抽象说理再回到具体

「护住身体」原来的结构是：提问「会不会被烧坏」→「先说道理」（一段抽象的复利曲线理论）→ 配图 → 回到亲身经历。作者反馈「复利曲线穿插在中间很生硬」。

修法：把道理挪到这一节最前面直接讲，图紧跟着道理，然后再引出「会不会被烧坏」这个问题接故事。道理不再是被一个问题打断之后插进来的东西，而是这一节开门见山的第一句话。

一般规律：一段说理如果需要靠「先说 XX」这种报幕式起手才能起头，大概率是它被硬塞进了两段本可以直接衔接的内容中间，试着把它挪到自然的起点，去掉报幕词。

### 4. 承诺和兑现不能被岔开

原句「我烧坏过一次，下面拿自己当反面教材」后面接的却是一段理论，读者刚被吊起胃口就被岔开。作者原话：这段话「过渡到先说道理，就很生硬」。

规律：一句话如果承诺「下面讲 XX」，紧接着就必须是 XX，中间不能插别的内容。如果确实需要先讲点别的，要么把承诺句往后挪到内容前面紧贴着，要么干脆去掉承诺句让内容自己接上。

### 5. 标题必须是这一节坐实了的结论或者列出的具体内容，不能借一个听着高级但没坐实的词

「长期主义」当过一节的标题，被作者否了两次：「长期主义不好吧？不太贴切吧」，最终定稿是「护住身体」。原因是这一节实际讲的是「身体是本金，不能拿它换短期结果，所以划睡眠健身的硬底线」，「长期主义」这个词在正文里只出现了一次，撑不起一个标题。

另一个例子：「找到大头之前」被否掉（「不太合适了吧」），改成直接列出这一节讲的三件事：「打工，保守创业，激进创业的探索」。

规律：标题要么是这一节明确写出来（不止一次）并坐实的结论，要么是这一节列举的具体内容本身，不能是一个感觉贴题但正文没坐实的抽象词。

### 6. 平行结构里，主语的「类型」要统一

「塔勒布在《反脆弱》里给了半个答案，蒂尔在《从 0 到 1》里给了另外半个」，两边都是「人名 + 书名」。后一句「《反脆弱》的说法是……」和「《从 0 到 1》说的是另一头」，两边都用书名做主语，不是一边人名一边书名。

规律：两个并列分句如果结构对称，主语的类型（人名 / 书名 / 其他）要保持一致，哪怕这意味着要在后面再重复一次前面出现过的书名。人物第一次出现要带书名，但如果后续有和另一个人物的平行句式，平行的那一侧也要带书名，不能因为「已经提过一次」就只用人名。

### 7. 一个概念全文只用一种说法，包括已经写完的段落

「三件事」最初叫「打工、个人与企业的咨询与培训、探索」，作者要求统一成「打工、保守创业、激进创业的探索」之后，这个说法在全文出现了三处（标题、正文首次提出、尾声回顾），三处都要改，不能只改第一处。

检查方法：改一个术语或说法的时候，全文搜索这个概念的所有历史说法，一次性都换掉，不要留下不同段落用不同措辞指代同一件事的情况。

### 8. 判断要有支撑，优先用数字和反推

「国内数据库市场 500 亿，对比白酒 6000 亿、手机全球 10000 亿美元」「股权 0.1% 想变现 1 个亿，反推公司得值 100 亿到 1000 亿」「这一优化将 TiKV 前台写入 RocksDB 的最大延迟减少了约 100 倍」。有数字就摆数字，不只给形容词。这条在技术讲解和个人随笔里都成立。

### 9. 主动承认局限、猜测和不确定，不假装全知

「我经验不足，给不出一个答案，就让时间来回答吧」「无，全凭脑子（易失性内存）现编（尤其是 MySQL 的部分），如有错误，欢迎指正」「尽管我不能 100% 确定它属于这个分类，但我认为分类错了也问题不大」「本文此处内容有缺失，待日后有时间再补充」。这条几乎每篇技术文章都有，是判断这段文字像不像本人写的重要信号，通用 AI 写作很少主动说「这段我不确定/我猜的/我还没研究」。

## 三、禁止清单

- 不用 Markdown 双星号加粗正文（公众号、小红书不解析 Markdown，星号会原样显示）。注意：2021-2023 年的旧技术文章里用过双星号加粗定义性术语，那是旧习惯，现在的规矩以最新的为准，不要学旧文章里的加粗用法。
- 不用英文破折号「——」，需要停顿或补充就用句号断句、逗号，或者括号。
- 不用英文直引号，引用用「」，书名用《》。
- 汉字与英文字母、数字之间加空格：「AI 时代」「300 万」「40 岁一个亿」。
- 不用装饰性封面图/海报式视觉开场，直接文字开头。
- 「先说 XX」这类报幕式起手式：能去掉就去掉，让内容自己接上前一句。
- 连续的一句一段：合并成完整段落，AI 稿爱用「我知道。」「会。」这种独立成段的短句制造节奏，本人不这么写。
- 每段结尾拔高升华：查一下是不是每段最后都有一句漂亮总结，有就删掉或者改成大白话。
- 「不是 X，是 Y」「A 是赚的，B 是亏的」这类工整对仗：一篇最多留一两处，多了是 AI 味。
- 结尾主动升华金句：不要，改成老实小结或者自嘲式收尾。
- 文中出现的旧「不讨人厌的广告」自我推广段落（早期技术文章的固定收尾）：不用再写，现在博客主题自带作者信息栏，不需要正文里手动插一段自我推广。

## 四、参考资料

- 这份 skill 覆盖个人随笔/判断输出类写作，技术讲解类文章的详细写法（大量编号、小标题拆知识点、每个方案配正反例）不在覆盖范围内，混用会打架，需要时单独总结。
- 公众号发布：博客用 SVG 配图没问题，但微信公众号自己的渲染器不支持 SVG 里的 pattern/clipPath（会把斜线纹样铺满整个画布），发公众号前要把配图转成 PNG，这个问题在「目标：40 岁赚一个亿」发公众号时实测遇到过。
- 改稿流程：拿自己写/改过的稿子和 AI 生成的原文对比，一处一处总结改了什么、为什么改，把新发现的规律补回这份 skill 对应的风格要点或禁止清单下面，不要凭空扩写规则（这个方法参考自 @dotey 在 X 上分享的「写作风格 Skill」思路）。
- 跟作者讨论文章结构时用树形列表展示大纲，不要用标题层级（不要 `##`/`###`，也不要 1、2、3、4 编号），每一条要具体、带实际内容（数字、事实、关键句），方便作者一眼核对内容对不对。
- 幽默手法库（个人博客语境下可用，不是每篇都要用，视内容和心情选用）：自称第三人称权威（「黄金架构师观点：……」）、整篇套用一个夸张文体（把技术文章写成法医鉴定报告）、给竞品公司起谐音/表情符号外号、自嘲式免责声明。这些是调味，不是主菜，用多了会盖过内容本身。
- 结尾水印：个人随笔/判断输出类文章，正文最后一段之后单独一行，加一句斜体声明「*本文是作者口述，AI 整理生成，如有问题，Claude 负全责。*」，用单星号斜体，不是双星号加粗。从「目标：40 岁赚一个亿」开始固定，以后同类文章都要加，作者原话：「这个文章底下斜体这句话以后是相当于我的一个水印吧」。
